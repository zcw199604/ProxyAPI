# 变更提案: 账号请求、Token 与金额统计

## 需求背景

当前仓库已经在 `sdk/cliproxy/usage` 生成逐请求 usage record，并由 `internal/redisqueue` 将记录放入内存队列；管理 API 可以看到单个账号进程内的成功/失败次数、最近请求桶和最近一次 Claude/Codex 额度信号，但没有持久化的账号级历史统计，也没有统一的模型价格与金额计算。

用户希望增加类似 sub2api 的账号统计能力，至少覆盖请求数、Token 数和总金额；模型价格可以从 sub2api 的模型价格文件同步；同时允许针对单个账号设置独立价格，而不影响全局价格或其他账号。

本方案以 sub2api 当前模型价格文件为兼容输入格式：

`https://raw.githubusercontent.com/Wei-Shaw/sub2api/main/backend/resources/model-pricing/model_prices_and_context_window.json`

该文件采用 LiteLLM 风格的 `input_cost_per_token`、`output_cost_per_token`、缓存价格和图片价格字段。同步后的价格只作为本地计费目录，不改变路由、上游请求或账号额度调度。

金额口径默认使用价格源的 USD；本切片不做汇率换算。若后续需要人民币展示，可在查询层增加只读换算，不修改事件中的 USD 原始金额。

## 变更内容

1. 新增持久化的逐请求账号 usage event，记录请求结果、各类 Token、模型、账号身份和计费价格快照。
2. 新增账号/模型/日期维度的聚合查询，返回请求数、成功/失败数、输入/输出/缓存/推理/总 Token 和总金额。
3. 新增 sub2api 模型价格同步器，支持启动同步、手动同步、定时同步、哈希/ETag 校验、旧版本回退和模型名规范化。
4. 新增账号级价格覆盖规则，支持精确模型、通配模型和账号默认规则，并定义明确的价格优先级。
5. 新增 Management API，供现有管理中心或外部面板查询统计、查看/更新价格、触发同步和查看同步状态。
6. 保留现有 usage queue、`auth.Success/Failed`、额度观察和调度冷却语义；新统计作为独立 usage sink 接入，不改写 `internal/translator`。

## 范围边界

- **范围内:** 单实例可用的持久化账号统计后端；请求/Token/金额统计；sub2api 价格目录同步；账号级价格 CRUD；Management API；配置、迁移、测试和必要知识库更新。
- **范围外:** 管理中心前端页面；真实供应商账单或余额查询；改变账号轮询、额度冷却或重试策略；用户扣费/充值体系；把账号级价格用于下游 API Key 计费；多实例跨节点实时汇总（预留存储接口，后续可接共享数据库）。
- **拆分说明:** 第一阶段先建立稳定的事件与价格闭环；可视化页面和共享数据库适配属于后续切片，避免把前端和部署架构变化混入本次实现。

## 影响范围

- **模块:** `sdk/cliproxy/usage`、新增 `internal/usage` 统计模块、`internal/config`、`cmd/server` 生命周期、Management API、HelloAGENTS 知识库。
- **文件:** usage record/manager、统计存储与聚合、价格同步与解析、管理 handler/routes、配置示例、测试和文档。
- **API:** 新增 `/v0/management/account-stats`、`/v0/management/account-pricing`、`/v0/management/pricing/*`；现有 API 保持兼容。
- **数据:** 新增本地统计数据库（默认 `data/usage.db`）及 schema 版本；事件为只追加，日聚合可重建；不修改既有 auth 文件格式。

## 核心场景

### 需求: 持久化账号统计
**模块:** `internal/usage`、`sdk/cliproxy/usage`

将每个 provider attempt 作为一条事件写入统计存储；本方案中的 `request_count` 定义为实际发出的 provider attempt 数，而不是客户端重试前的逻辑请求数。事件即使没有上游 Token，也必须计入请求数；失败请求计入失败数，Token 和金额可以为 0 或未定价。

#### 场景: 请求成功并返回 Token
统计事件包含稳定 `auth_id`、`auth_index`、provider、请求模型、上游/规范化模型、Token breakdown、成功状态和价格快照；账号总请求数、Token 数和金额同步增加。

#### 场景: 请求失败或无 Token
事件仍被保留，失败请求数增加；金额为 0 或 `unpriced`，不能因为缺少 usage 字段而丢失请求统计。

#### 场景: 进程重启后查询
历史事件和聚合仍可查询，不能依赖 `Auth.Success/Failed` 等内存字段。

### 需求: 模型价格同步
**模块:** `internal/usage/pricing`

从配置的 sub2api URL 拉取 LiteLLM 风格 JSON，校验字段、负值和模型键后原子替换价格版本。网络失败时继续使用最近一次有效目录或内置空目录，并暴露同步状态。

#### 场景: 自动同步成功
保存源 URL、获取时间、内容哈希、模型数和版本号；新请求使用新价格，历史事件仍使用写入时的价格快照。

#### 场景: 源文件不可用或格式变化
不覆盖最后一次有效目录；记录可诊断错误；已有统计继续可读，未定价请求明确标记为 `unpriced`。

### 需求: 账号独立价格
**模块:** `internal/usage/pricing`、Management API

管理员可以按 `auth_id`/`auth_index` 设置一个账号的模型价格，支持 token、按请求和图片等计费模式；覆盖只影响该账号的新事件。

#### 场景: 价格匹配
价格优先级为“账号精确模型 > 账号通配模型 > 账号默认 > 全局同步目录 > 未定价”。同一层级按显式优先级和更新时间确定性选择。

#### 场景: 修改价格后查看历史
修改只影响未来事件；历史金额不重新计算，查询可以看到事件使用的价格版本/来源。

### 需求: 统计查询
**模块:** Management API、`internal/usage`

按时间范围、账号、provider、模型和粒度查询汇总，并返回定价覆盖率和未定价数量，便于外部面板展示和审计。

#### 场景: 单账号汇总
返回请求数、成功/失败数、输入/输出/缓存读/缓存写/推理/总 Token、总金额（USD）和 `priced/unpriced` 数量。

#### 场景: 按日/模型展开
同一账号可按日或模型分组；聚合结果与逐请求事件可通过 `request_id/event_id` 对账。

## 风险评估

- **风险:** usage sink 写入失败导致统计丢失。**缓解:** 事件先写本地持久化存储，使用唯一 `event_id` 幂等；写入失败记录错误并保留可重放的本地 spool，不静默丢弃。
- **风险:** 价格源漂移、模型别名误匹配或价格字段含义变化。**缓解:** 保存源哈希和价格快照；精确匹配优先，模糊匹配必须显式映射；未知模型标记 `unpriced`；同步失败保留旧版本。
- **风险:** 浮点误差造成金额累计偏差。**缓解:** 价格归一化为整数 nano-USD，使用整数/大整数乘法并在 API 层格式化为十进制 USD。
- **风险:** 统计库增长影响磁盘和查询性能。**缓解:** 事件表按时间索引，日聚合表用于常规查询；提供保留期、归档/重建命令，默认查询优先走聚合。
- **风险:** 账号标识变化或账号删除后无法归属历史。**缓解:** 事件同时保存稳定 `auth_id`、展示用 `auth_index` 和当时的账号名称/provider 快照；查询不依赖当前 auth 文件存在。
- **风险:** 管理 API 暴露敏感信息。**缓解:** 只返回账号标识和统计，不返回 API key、OAuth token 或完整请求体；复用现有 Management API 鉴权和输入校验。
